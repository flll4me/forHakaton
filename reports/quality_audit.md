# Комплексная проверка качества — Grand Mobile Support Copilot

Дата: 2026-10-30. Версия: модель A (TF-IDF + LogReg + правила), выбранная по заранее заданному критерию на control v1.
Классификатор в ходе проверки не менялся и не переобучался; test не использовался для настройки моделей, правил и порогов;
отдельные ошибки test не просматривались (по test приводятся только агрегаты).

Реальные вызовы LLM API **не выполнялись** (ключа в среде нет). Ветка LLM проверена через подставные провайдеры
и через официальный SDK `anthropic` / httpx, направленные на локальный HTTP-сервер, который имитирует
зависание, HTTP-ошибки и битый ответ.

## 2. Качество черновиков (повторная оценка)

Методика та же: шкала 1–5 (5 — можно отправлять как есть; 4 — корректно и по правилам; 3 — корректно, но неполно;
2 — неверный тип ответа из-за ошибки категории; 1 — недопустимо: обещание, выдуманный пункт, чужой язык),
случайная выборка из valid по языку черновика, оценщик — разработчик (Claude), не носитель kk/uz.

| язык | n | средняя | доля ≥4 | доля ≤2 | раунд 1 (другая выборка) |
|---|---|---|---|---|---|
| ru | 15 | **3.47** | 60% | 13% | 3.73 |
| kk | 8 | **2.88** | 25% | 25% | 3.12 |
| uz | 15 | **3.53** | 67% | 13% | 3.53 |
| все | 38 | **3.37** | 55% | 16% | 3.53 |

- В valid всего 8 черновиков на kk, и среди них есть два одинаковых обращения, поэтому оценка по kk ненадёжна.
- Выборки раундов разные и малые; падение 3.53 → 3.37 в пределах шума и не означает ухудшения генератора.
- Одна оценка 1 (kk): русский текст с одной буквой «һ» определён как казахский — черновик на казахском (O2).
  Запрещённых обещаний и выдуманных пунктов в выборке нет.
- Основная причина оценок ≤2 — ошибки категории: обжалования, распознанные как жалоба на игрока
  (4 из 6 случаев). Это ограничение классификатора, а не генератора (O1).

## 4. Сквозные тесты (`tests/test_e2e.py`, 19 тестов)

HTTP `/triage` → категория, приоритет, факты, черновик, cited, needs_human и reasons. Для каждого ответа проверяются
инварианты: схема контракта, непустой черновик, отсутствие обещаний, пункты только из rules.json, каждый номер в тексте
есть в cited, у эскалации есть причина. Сценарии: оскорбление ru (пример контракта), читы, DM ru/uz, kk (cp1251),
апелляция, платёж ru/uz, возврат, взлом, помощь с машиной, оффтоп, пустое сообщение, угроза вне игры, неверный пункт,
попытка внушить ответ через текст обращения, неоднозначная жалоба, «внушение», которое выполнила подставная LLM
(отклонено проверками), и пакетный `predict` (битая строка, ошибка схемы, причинный порядок для повторов,
реплика админа во входе).

Сквозные тесты сразу нашли три дефекта: F1, F3 и F7.

## 5. Отказы LLM (`tests/test_llm_failures.py`, 22 теста)

| Ситуация | Поведение |
|---|---|
| `LLM_ENABLED=false` (новый общий выключатель) | NullProvider, причина в `/health` (`llm_disabled_reason`), черновики по шаблонам |
| `LLM_PROVIDER=anthropic` без `ANTHROPIC_API_KEY` | При старте — NullProvider с причиной «не задан ANTHROPIC_API_KEY» и предупреждение в лог. Раньше: на каждом сложном тикете непонятное «LLM ошибка: TypeError» и лишняя эскалация |
| Ключ пропал после старта | Ошибка «LLM: не задан API-ключ» → шаблон |
| Нет LLM_MODEL / LLM_BASE_URL / неизвестный провайдер | NullProvider с причиной |
| Таймаут (сервер не отвечает) | «таймаут LLM» за ≈ LLM_TIMEOUT_S без ретраев; весь тикет < 5 с; шаблон + needs_human + причина |
| HTTP 500 / 529 / 429 / 401 | Типизированная ошибка → шаблон + needs_human |
| Битый ответ / невалидный JSON | Ошибка → шаблон |
| Сеть недоступна | «LLM недоступен (сеть)» (на Windows может проявиться как таймаут) |
| Оценка стоимости выше лимита | Вызов не выполняется |
| Короткое типовое обращение при неработающем LLM | LLM не вызывается, ответ не меняется |
| То же для `openai_compatible` (таймаут, 500, мусор) | Шаблон |
