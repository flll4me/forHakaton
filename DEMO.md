# Демонстрация Grand Mobile Support Copilot

## Запуск

```bash
make demo                 # Linux/macOS
.\tasks.ps1 demo          # Windows (PowerShell)
```

Команда сначала прогоняет `scripts/demo_check.py`: все 16 демо-обращений сверяются с ожидаемым результатом и с
инвариантами безопасности. Если хоть одно не прошло, показ не запускается. Затем стартуют:

- админка — http://localhost:8501 (Streamlit, источник «Демо-сценарий»);
- API — http://127.0.0.1:8000/docs (Swagger), `/health`, `POST /triage`.

Нужны распакованные `rules.json` и `taxonomy.json` из архива кейса (`data/raw/handout/`) и обученная модель
(`models/classifier.joblib`, `make train`). Без модели сервис работает только на правилах и чаще передаёт обращения
человеку. Демо-обращения (`demo/demo_tickets.jsonl`) написаны вручную, ники вымышлены, данных кейса в них нет.
Действия Send / Edit / Escalate на показе пишутся в отдельную базу `data/processed/feedback_demo.sqlite`.

Перед показом:
- первый запуск скачивает модель эмбеддингов (~470 МБ) — запустите демо заранее при наличии сети;
- офлайн задайте `HF_HUB_OFFLINE=1`, чтобы модель бралась из кэша;
- при 8 ГБ ОЗУ API и админка помещаются вместе только с `OPENBLAS_NUM_THREADS=1` (задаётся автоматически);
- `LLM_PROVIDER=none` (по умолчанию): черновики по шаблонам, без внешних вызовов и без ключей.

## Сценарий показа (≈7 минут)

Очередь сортируется по приоритету: сверху p0, ниже — остальные. Колонка «сценарий» подсказывает, что показывает строка.

| Шаг | Обращение | Что показать | Что сказать |
|---|---|---|---|
| 1 | demo-01, пример из контракта | Ответ совпадает с примером из задания: `complaint.insult`, p2, ник, пункт 2.1, вложения. В черновике подсвечены цитаты, рядом полный текст пункта из `rules.json` | Цитируются только пункты, найденные поиском и проверенные: выдуманных пунктов на 1000 обращениях валидации — 0 |
| 2 | demo-05, платёж | p0, «нужен человек», причины выделены красным, в черновике нет обещания вернуть деньги | Платежи, апелляции, взлом и угрозы всегда уходят человеку — это правило, а не модель |
| 3 | demo-06, апелляция | `complaint.admin`, срок подачи (3.4), просьба приложить скриншот наказания, решение принимает администрация | Сервис не обещает разбан и не выносит вердикт |
| 4 | demo-08, угроза вне игры | p0 и обязательная эскалация, даже при низкой уверенности категории | Уверенность модели показана честно; при сомнении — человек |
| 5 | demo-02 и demo-03, kk в cp1251 и uz | Казахский текст с битой кодировкой восстановлен, ответ на kk; узбекский — ответ на uz | Язык ответа — язык игрока; украинский и смешанный текст отвечаются по-русски |
| 6 | demo-12…14, серия повторов | Первое обращение новое, следующие два помечены как повтор | Повторы одного игрока за час не засоряют очередь |
| 7 | demo-10, demo-16 | Автоответ без человека: кнопка эвакуатора, просьба уточнить | Автоматически закрывается только то, где не нужно решение админа |
| 8 | Вкладка «Новое обращение» | Ввести своё обращение (можно попросить жюри) | — |
| 9 | Вкладка «О системе» | Метрики из отчётов и оговорки | Цифры не правились вручную: страница читает `reports/*.md` |
| 10 | Swagger `/docs` | `POST /triage` с примером из контракта; `?debug=true` | Тот же пайплайн доступен как HTTP API и как пакетный `make predict` |

Действия админа: Escalate или Edit на любом обращении → вкладка Feedback. Send для обращений с needs_human
недоступна, пока текст не исправлен. В игру ничего не отправляется.

## Если что-то пошло не так

| Проблема | Что делать |
|---|---|
| `demo_check` упал | Не показывать. Запустите `python scripts/demo_check.py` — он покажет, какое ожидание не выполнено |
| Нет сети, эмбеддинги не скачаны | `EMBEDDINGS_ENABLED=false`: поиск только BM25, `/health` покажет `rag_dense: false`. Сценарий проверялся с эмбеддингами |
| Не хватает памяти | Запустите только админку: `.\tasks.ps1 dashboard` с `DEMO=1` |
| Порт занят | `.\tasks.ps1 demo -Port 8010` (API); админка — `streamlit run dashboard/app.py --server.port 8502` |
| curl в Windows PowerShell 5.1 показывает кракозябры | Это особенность `Invoke-RestMethod`: он не декодирует ответ как UTF-8. Используйте Swagger или `curl.exe` |

## Что честно сказать о границах

- Метрики: accuracy категории 0.77 на независимой выборке из 100 обращений; разметка выполнена разработчиком, а не
  экспертами Grand Mobile.
- LLM-режим реализован и покрыт тестами отказов, но реальные вызовы API не выполнялись: показываем шаблоны.
- Слабые места: обжалования иногда распознаются как жалобы на игрока (черновик неверного типа, но решение всё равно
  принимает человек); данных на казахском мало.
